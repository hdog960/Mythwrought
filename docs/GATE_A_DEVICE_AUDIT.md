# MYTHWROUGHT — Foundation Gate A device audit (OPEN)
Status: **manual validation protocol, not a passing hardware or art approval**. Continue v0.09 engineering foundation while v0.10 Gate A is open.

## New read-only v0.10 evidence feature
In the landscape game, open **☰ → GATE A · DEVICE CHECK → RUN DEVICE CHECK**. The report samples recent foreground gameplay frame intervals (up to 360), viewport/controller geometry, WebGL chunk count and whether the current world matches a readable saved snapshot. It performs one round-trip with a newly named **temporary unrelated localStorage key** and removes that key; it **does not edit or repair** world saves, journals, backups, world chunks or user settings. Browser storage quotas are estimates, not permanence guarantees. A browser screenshot is not an actual iPhone test. Copy the report manually if you wish to share it. No report is sent to any server or stored in a world save.

## Optional IndexedDB snapshot vault — backup and controlled restore
A dedicated settings section offers **BACK UP THIS WORLD**, **SHOW DEVICE BACKUPS**, **PREPARE JSON DOWNLOAD**, **RESTORE SELECTED**, and **DELETE SELECTED**. This is an *opt-in supplemental copy* of the currently loaded schema-1 world, not a replacement for canonical localStorage saves or an automatic migration. Save keys, selected seed, original world generation and v0.09 journal/previous-good files are unchanged. Each IndexedDB snapshot is written transactionally and read back with a checksum and schema/seed check. Up to **six snapshots per seed** are retained; none are silently rotated out. Bad backups are rejected, never made into active worlds.

To make a separate backup: open landscape ☰ settings, press **BACK UP THIS WORLD**, wait for a verified confirmation, optionally press **SHOW DEVICE BACKUPS**, select a snapshot, press **PREPARE JSON DOWNLOAD**, then tap the separate **DOWNLOAD VERIFIED JSON BACKUP** link. Keeping a JSON file outside the website's data is essential: Safari clearing/evicting website data may erase **both** localStorage and IndexedDB, including this vault.

Restoring a selected snapshot requires explicit confirmation *even if the seed matches*. Validated restore uses the existing `saveWorldSafe` v0.09 logic to preserve the last verified live primary in the previous-good backup or preserve damaged raw bytes separately. Declining restore changes no world data; deletion also needs confirmation and applies only to the selected vault snapshot. Never test damage by corrupting a valuable world or changing browser storage manually on a real device.

**Limitations / unfinished Gate A work:** IndexedDB provides atomic *supplementary* snapshots; this is **not** a transactional production save system, a migrated canonical save, cloud/offsite backup, continuous auto-backup, guaranteed storage persistence, native iOS file backup, or verified Safari hardware behavior. The gate remains OPEN until real iPhone tests and architectural durability requirements are satisfied.

## Opt-in verified save mirroring — experimental, Gate A still OPEN
Settings → **VERIFIED SAVE MIRROR** is **OFF by default**. Enabling it stores one explicit preference; subsequent successful canonical `localStorage` saves enqueue a small delayed IndexedDB copy, serialized per seed. It never changes any existing per-seed schema-1 key, v0.09 journal or user-owned exported JSON. On-device mirror records retain the **latest and previous verified copy in one IndexedDB transaction**. A copy is only described as verified after read-back and validation. Corrupt or mismatched mirror records cause **fail-closed refusal** rather than silent overwrites. The canonical saved world stays playable if the mirror fails, and there is no automatic recovery.

**SYNC CURRENT SAVE** manually verifies an existing canonical local save then awaits the mirror; **CHECK MIRROR** reports health of both copies. Select current/previous, **PREPARE JSON EXPORT**, then use the separate **DOWNLOAD VERIFIED MIRROR JSON** link. **RESTORE SELECTED COPY** always requires an explicit confirmation; it validates the seed, checksum and schema and uses the existing previous-good local backup path. Never test real-world corruption on a valued save. Switching the mirror off prevents new copying and does not delete old records.

**Important limits:** This is a supplemental opt-in mirror, **not** an IndexedDB canonical-save migration, complete production transaction/synchronization system, cloud backup or guarantee against web-data eviction. Current and previous copies are in the **same browser data partition** as other site data; a browser purge/eviction can erase everything. An in-flight IndexedDB transaction might never finish when Safari force-quits; the mirrored copy could lag the canonical save. Export JSON outside the website. Do not report a queued mirror as verified.

Settings → **3D pixel workload** adds Balanced (the old rendering cap, default), Battery saver and Economy. The latter two lower only the internal WebGL framebuffer pixel count; **left and right grips, canvas CSS viewport and touch targets do not move**. No claimed iPhone FPS, battery or thermal improvement without actual hardware measurements. The diagnostic report now includes framebuffer resolution and selected preset. Test all three on a real landscape iPhone, noting textural clarity/readability and 10+ minute thermals before accepting a setting.

## Foreground rendering and chunk-work continuity — browser evidence only
A foreground-only animation driver suspends WebGL rendering when the document becomes hidden, on pagehide and on WebGL context loss. It resumes at most one frame loop after a visibility or Back/Forward Cache return; previously held movement/aiming inputs must not remain stuck and inactive time must not become simulated gameplay time. A bounded chunk-upload cadence can spread heavy mesh builds over a few visible frames without changing chunk order, world saves or the playable 3D viewport. A failed GPU upload retains the previous chunk buffer instead of immediately deleting it. Gate A **DEVICE CHECK** now includes estimated mesh upload count, deferred frames and longest measured upload.

The new Chromium lifecycle regression emulates tab visibility, verifies stopped rendering and no stuck movement, exercises pagehide/pageshow, traverses a negative chunk window, reopens Settings and captures screenshots while preserving original seed-save bytes. **This does not replace real iPhone Safari or installed Home Screen testing.** Physically test interruptions, app switching, force quit and low-memory/thermal conditions, recording any retained input or blank world, before accepting Gate A.

## Player-owned real device verification checklist
Test **Safari** and separately test **Add to Home Screen** at https://hdog960.github.io/Mythwrought/:
1. Open landscape, check central viewport is completely unobstructed, notch and safe areas do not clip grips or footer. Use both thumbs at once for movement, look, jump, MINE/PLACE; verify horizontal controls are intuitive and the help menu scrolls.
2. Play 10+ minutes across several chunk seams and multiple edits. Run the device check *after active gameplay*, copy results, note thermal feel, pauses, browser reloads, rendering glitches and frame timing. Compare landscape sizes and large-controller setting. Rough software-reported FPS is **not** a certified iPhone benchmark.
3. Save, export JSON, close/force-quit Safari, reopen and inspect the same edits and selected seed. Repeat in installed Home Screen mode; check what is and is not retained after app switching and orientation changes. Export again. Do **not** clear site data before obtaining your backup.
4. Check damaged-save protection using a **separate disposable test seed only**, never by manually corrupting a valued real save. Verify the app cannot silently erase an unreadable slot, and that it lets you choose another seed or import a previously exported backup. Current IndexedDB transactional migration is **not implemented**.
5. Review actual world artwork, materials, atmosphere, animation and eventual character/cave art. Mark art **unapproved** until an explicit personal visual review approves it. Current landscape is prototype engineering art, not a final premium fantasy biome.
6. Document airplane/offline behavior but do not claim offline support: a service worker and validated offline caching are future milestones. Browser storage eviction, low-memory termination and real-iPhone thermal limits remain risks.

## Gate decision
**Gate A stays OPEN** until actual iPhone Safari and installed Home Screen control/save/performance evidence is collected, production-scale save durability is addressed, and the required visual acceptance is explicitly granted. The automated Chromium test is useful regression evidence, never a substitute for this manual verification. Do not promote v0.10 or unlock v0.11 by counting this document as a passing device test.
