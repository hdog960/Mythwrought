# Global ecology ticker and capped region selection — detached source research

Pure optional preflight scheduling component, **not** live PopulationManager. Source owner `src/mobs/ecology.mjs` uses `INTERVAL=0.5`, `MAX_REGIONS=64`, `REPLENISH=12`, increments `time` by `min(1,seconds)`, and chooses `regions[cursor++ % min(length,64)]` only at a global tick after nonempty regions. For invalid selected regions the cursor still advances; for new records after 64 stored, eviction checks the first entry with `next <= currentTime-12` or refuses admission. This detached module mirrors those conditions without calling `engine.spawn` or changing source state.

`advanceGlobalEcologyClock` returns an immutable clock and one pending region ticket. Caller may use the existing original-engine-backed `prepareOriginalMobPoll` and `settleOriginalMobPoll` to prepare the source schedule. `commitGlobalEcologyRegion` accepts a valid original regional schedule from that tick and stores it in a capped immutable 64-record ledger. Tickets are certified with private WeakMap provenance and single-use consumption; no second tick until the pending ticket is committed. This makes the research transition stricter than the source manager and prevents accidental double polls in future integration. Original source's away/dormant/reconcile, 64-region eviction during collisions, direct MobEngine admissions and saves are untouched. No game integration or new M7 actual natural-birth evidence.

Native focused Node source file exists but remains unrun. Six focused test bodies cover exact original time/cursor math, full-cap rejection, first stale eviction, 64-region prefix, malformed input/forgery and empty/invalid sites. Preserve existing offline PWA blocker and all release checks.


## Focused source fault corrected

The initial global-clock research version moved an existing Map key to the end when updating a regional record. The ORIGINAL `PopulationManager.#regions` is a JavaScript Map and `Map.set(existingKey,...)` preserves original insertion order. The coordinator now replaces existing regional entries in place while appending only new keys, so first-stale selection matches the source manager. Additionally the first 64 slots take a minimum of 32 seconds to populate at the original half-second ticker, so the first slot is normally already stale at slot 65; the earlier test's assumption that 64 full records would automatically refuse a newcomer was invalid and was repaired. Added a true source high-water replenishment test: after authentic birth high-water of 1 followed by a decline, region 0 receives an additional 12-second wait and must NOT be evicted; the next oldest stale region 1 is evicted first. No live game code or CI workflow changed.


## Fix: reject source reconcile BEFORE consuming global tick

Previously `prepareGlobalMobTick` invoked `advanceGlobalEcologyClock` (which consumes the certified clock) before checking the original `PopulationManager.#reconcile` responsibilities. An ordinary near-dormant creature would cause a correct refusal but permanently consume its clock, preventing a safe same-clock retry after the original owner had reconciled. New source-only, dependency-free `ecosystem-tick-preview.mjs` computes the same original 1s-clamped due decision without side effects. The certified `previewGlobalEcologyTick` checks actual clock ownership, then both source global advancement and preflight use that single timing core. Preflight now checks the source reconciliation guard **before** calling consuming advance; failed reconciliation leaves original clock unchanged, and successful original-manager reconciliation allows the same tick to resume. Invalid observer and forged clocks still fail closed.
