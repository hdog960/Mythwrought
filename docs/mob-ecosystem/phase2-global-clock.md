# Global ecology ticker and capped region selection — detached source research

Pure optional preflight scheduling component, **not** live PopulationManager. Source owner `src/mobs/ecology.mjs` uses `INTERVAL=0.5`, `MAX_REGIONS=64`, `REPLENISH=12`, increments `time` by `min(1,seconds)`, and chooses `regions[cursor++ % min(length,64)]` only at a global tick after nonempty regions. For invalid selected regions the cursor still advances; for new records after 64 stored, eviction checks the first entry with `next <= currentTime-12` or refuses admission. This detached module mirrors those conditions without calling `engine.spawn` or changing source state.

`advanceGlobalEcologyClock` returns an immutable clock and one pending region ticket. Caller may use the existing original-engine-backed `prepareOriginalMobPoll` and `settleOriginalMobPoll` to prepare the source schedule. `commitGlobalEcologyRegion` accepts a valid original regional schedule from that tick and stores it in a capped immutable 64-record ledger. Tickets are certified with private WeakMap provenance and single-use consumption; no second tick until the pending ticket is committed. This makes the research transition stricter than the source manager and prevents accidental double polls in future integration. Original source's away/dormant/reconcile, 64-region eviction during collisions, direct MobEngine admissions and saves are untouched. No game integration or new M7 actual natural-birth evidence.

Native focused Node source file exists but remains unrun. Six focused test bodies cover exact original time/cursor math, full-cap rejection, first stale eviction, 64-region prefix, malformed input/forgery and empty/invalid sites. Preserve existing offline PWA blocker and all release checks.
