## Geometry
src/liquids/presentation/mesh.mjs exports PRESENTATION_VERSION=1, PRESENTATION_IDS, buildLiquidMesh({engine,isLoaded,isOpen,cells,origin,maxCells=256,maxFaces=2560}), expandLiquidDirty(changed,{maxChanged=256,maxDirty=1792}).
Read engine.getCell(x,y,z) only for loaded/open coordinates. Host callbacks are synchronous, pure, and stable during a batch. Null is empty; valid records carry matching x/y/z, id, units 1..8. Explicit cells are uniquely owned by caller, no world scan. Neighbors may be sampled across owners; unloaded/solid neighbors suppress boundary faces until a host invalidation. Physical Y -210..256 inclusive. Origin is a physical integer point; all selected positions must be within 4096 per axis. Vertex positions relative to origin retain eighth-height precision far from world zero.
Each group has id, Float32Array positions and normals (xyz), Uint32Array triangle indices (WebGL2 UNSIGNED_INT); CCW outward winding. Four vertices/six indices per quad. Flat top units/8, exposed bottom, side strips above neighbor fill. Same-ID internal faces culled; unlike-ID coplanar overlap owned by lexically smaller ID (one two-sided face, provisional style policy), exposed taller strip owned by taller cell. No implicit liquid mixing or smoothing of physical volume. Group order is canonical IDs, NOT transparency draw order. Mesh batches cap input and faces and reject excess rather than truncating. Maximum output typed bytes = 120 per quad; default 307200 bytes, excluding temporary JS arrays, host buffers and staging. This is an isolated admission limit, NOT a production budget allocation. Host must account for all CPU/GPU/staging bytes against existing owner budgets and keep prior-good mesh on rejection.

## Optional bounded CPU mesh cache (additive v1)
src/liquids/presentation/mesh-cache.mjs exports createLiquidMeshCache({engine,isLoaded,isOpen,describeBatch,maxBatches=128,maxVisits=4,maxCells=256,maxFaces=2560,maxResidentBytes=1048576,maxStagingBytes=307200}). No runtime mount, GPU allocations or persistent game state. Host maps expanded dirty cells to existing unique physical owner/batch IDs (nonempty strings <=128 chars) and supplies a complete bounded batch description {origin,cells}; null means unavailable, [] is an explicit empty batch. All selected coordinates must be loaded before replacement; unavailable neighbors remain governed by mesh v1. Host ensures stable, pure reads and invalidates affected batches on all changes, including boundary load/unload, and explicitly drops retired owners. Do not build a second physical owner registry.

invalidate(ids) atomically admits deduplicated work or returns false when tracked resident/pending union would exceed maxBatches. Caller retains and retries rejected input. New invalidations update revision without queue duplication. step(limit=maxVisits) visits bounded initial FIFO entries once; failed/unavailable/stale/budget-rejected entries rotate to the tail. Each publication checks revision and exact typed buffer bytes; old CPU mesh remains on rejection. The result contains visited, published [{id,revision,bytes,empty}], deferred [{id,reason}], tracked, pending and residentBytes. get(id) returns current {id,revision,bytes,mesh} or null; drop(id) removes a retired batch and its queue work outside step; stats() returns tracked/pending/residentBytes. Mesh objects are structurally frozen; typed arrays are mutable in JavaScript, host must treat them as read-only, release old references and not retain unbounded copies. No async build, and no callbacks inside publication. Explicit invalidation during a build discards stale work. Empty publication clears prior CPU mesh; host must process the empty event.

Face limit is additionally bounded by floor(maxStagingBytes/120) before mesh creation. Resident typed bytes count each current mesh once; a replacement is admitted against net resident bytes and an independent candidate staging cap. These are provisional CPU typed-array caps, not total heap, GPU, owner, frame-time or production memory measurements. Temporary mesher JS arrays, old references, actual renderer buffers and upload staging must be bounded by the existing owner/height budget and host integration. GPU publication needs its own revision check, atomic upload/swap and rollback; CPU publication is not an atomic GPU replacement. No automatic terrain/physics edits, materials policy changes, or save changes.

## Optional simulation dirty-to-batch handoff (additive v1)

Host supplies synchronous pure batchesForCell(x,y,z) => string[] | null using its existing physical ownership and batch partition; [] means explicitly no resident batch, null means mapping not ready. No independent owner registry. Set maxBatchIds <= the target cache maxBatches. Limits constrain input, halo, mapping fanout and unique batches; malformed inputs or callback faults throw before admission. Returns frozen {accepted,reason,dirtyCount,ids}; rejection reasons mapping-unavailable, routing-budget or cache-budget. Rejection means retain and retry the entire dirty input, not discard changes; larger streams must be partitioned by the host before routing. Do not treat unknown/unloaded ownership as an empty batch. Host explicitly retires unloaded meshes and invalidates both sides on reload; new owners require initial population. Hold stable simulation/streaming read lease while routing and rebuilding; CPU publication is per batch, not a synchronized multi-owner GPU swap. On engine replacement rebind/recreate the cache with coordinated host ownership and invalidation. No automatic runtime mounting or save schema changes.

## Optional bounded draw planning (additive v1)
src/liquids/presentation/draw-plan.mjs exports planLiquidDraws({batches,materials,camera,forward,maxBatches=128,maxFaces=8192}). Supply cache-shaped unique {id,revision,mesh} records and a material map keyed by symbolic ID, with exact v1 mesh quad buffers. Camera is a finite world-space xyz point, forward is a nonzero finite direction. Material policy requires depthTest true, cull false, opaque depthWrite true, transparent depthWrite false and straight-alpha blending. Other lane descriptors remain owner-controlled; incompatible policies reject rather than silently reinterpret. No changes to prior mesh ABI.
Returns frozen {faces,opaque,transparent}, each pass an array of revision-tagged {batchId,revision,liquid,firstIndex,indexCount} ranges. Individual quads sort by projected camera-space centroid depth, opaque front-to-back and transparent back-to-front across all supplied batches/materials; stable ties use batch ID, canonical liquid order and index offset. Adjacent ascending contiguous ranges coalesce without altering order. Use UNSIGNED_INT with byte offset firstIndex*4. No vertex buffer duplication or mutation. Approximate centroid sorting does not solve intersecting surfaces, per-pixel ordering, refraction or order-independent transparency. Work bounded by admitted faces (O(F log F), at most F draw ranges; default 8192 is a provisional CPU work cap, not a measured phone draw-call target). Host supplies a culled visible set, must reject over-budget plans rather than publish truncated geometry, validate revision/material/camera state before drawing, render after opaque world geometry, bind existing buffers, restore full GL state, and coordinate actual GPU budgets, batching and performance before mounting. No host runtime changes.
Native deterministic fixtures use contract-shaped quads; draw-plan-webgl2.html is a standalone 64x64 WebGL2 pixel fixture with opaque occlusion and two blended transparent layers, test-only colors. No actual game visual or performance qualification is implied. Browser fixture requires a functioning WebGL2 context.

## Water-specific content proposals (additive v1)
src/liquids/water/content/features.mjs exports planWaterFeature({kind,origin,width=1,length=1,path,units=8,maxCells=256}) and describeWaterSurface({engine,isLoaded,isOpen,x,y,z,foamStrength=0.45}). Only Water B content, no new physics or renderer ABI. Pool uses a bounded X/Z rectangle at one physical Y; river uses an explicit nonrepeating face-adjacent horizontal path; waterfall uses explicit contiguous descending vertical cells. Combine separate plans only after host checks overlap and finite supply. Each frozen plan contains kind, explicit unique {x,y,z,id:'water',units} cells and exact requiredUnits. No terrain clearance, source registration, biome generation, inventory credit or injection authority. Max cells defaults to 256, hard cap 4096; validate physical bounds and integer volume. Host must stage placement, eligibility, overlap and finite supply atomically; source policies remain Water A's responsibility.

describeWaterSurface reads at most eleven loaded/open contract-shaped cells, never writes, and returns null for non-water/unavailable origin. Returns fill, exposedTop, shoreMask, fallMask, foamMask, foamStrength, material. Four directional bits are +X,+Z,-X,-Z; known solid neighbors contribute shore hints, vertical water continuity with empty side and empty cell below side contributes falling-looking edge hints. Unknown and unlike-liquid neighbors are not interpreted as empty or solid. Foam is restricted to known empty cell above; covered/unknown tops suppress it. This is intentionally conservative geometry-derived shading data, not velocity, simulated foam, shader rendering or physical geometry changes. Material remains the existing provisional transparent water descriptor; foam strength is a reversible visual proposal. Host may consume this bounded sample under the same stable read lease as meshing; no shared renderer edits or extra draw pass yet. No new terrain IDs or resource rules.
