# Shared liquid contract v1 — isolated candidate (2026-11-27)
Owner: Business Water A. Branch `business/liquids/water-core`. Creator's five-liquid scope: water, lava, acid, Amber Sap, Liquid Resonance (not water). No tar. This is a usable isolated interface, not a production integration or a claim that every gameplay mechanic is implemented.

## Import and state
`src/liquids/core/engine.mjs` exports `LIQUID_IDS`, `CELL_CAPACITY=8`, `LIQUID_CONTRACT_VERSION=1`, `createLiquidEngine(options)`. Stable string IDs: `water`, `lava`, `acid`, `amber-sap`, `liquid-resonance`; do not assign global block IDs. Each lane exports an isolated descriptor `{id,gravityLimit,lateralLimit}`: integer limits 0..8 per visited cell; gravity first, then total lateral limit. Water A exports `WATER_DEFINITION` from `src/liquids/water/physics/definition.mjs`. Nonwater definitions must be supplied by their owners, not hard-coded in the engine. The chosen 8 units/cell matches existing eight water height steps without treating full cells as sources.

`createLiquidEngine({isLoaded,isOpen,definitions,reactionRules=[],maxCells=8192,maxVisits=256,snapshot=null})`. Mandatory host callbacks `(x,y,z)=>boolean` return literal true only for loaded/eligible cells. Keep them synchronous, side-effect-free and stable during a tick. Use actual shared physical ownership from `src/world-height.mjs` when integrating; isolated kernel rejects Y outside -210..256 inclusive, does not alter legacy generation ceiling or seed. Safe integer world coordinates; no world scans. The cell record is frozen `{x,y,z,id,units,quantities}`; units integer 1..8, absence is empty. Optional extensive quantities (e.g. acid solute or resonance energy, names/units chosen by owners) are nonnegative integer counts, at most eight keys, each <=2^40; key pattern lowercase letter then lowercase letters/digits/hyphens, max 32 chars. Split transfers floor(q*n/originUnits), remainder retained at origin; merge sums, never silently truncates. Capacity/quantity overflow rejects transfer. No implicit creation, destruction or cross-ID blending.

## API
- `insert(x,y,z,id,units,quantities={}) => boolean`: explicit finite external injection; all-or-nothing; loaded/open compatible destination, available capacity. The caller must account for the source resource and only consume it on true. Default is finite; renewable springs/vents are NOT automatically enabled. Future bounded refill policy is an opt-in host adapter; no infinite bucket/source exploit.
- `extract(x,y,z,units) => frozen cell|null`: remove up to requested 1..8 units from a loaded cell; returns removed units/quantities. Can extract a newly obstructed loaded cell to support containment edits. Host must store transferred volume; no silent deletion. For block placement, reject an occupied cell until an atomic displacement plan or extraction succeeds; current kernel does not make world edits. No unsupported automatic displacement or material destruction.
- `getCell(x,y,z) => frozen cell|null`: stored state including unloaded; do not treat this as runtime collision query. `samplePoint(x,y,z) => {cell,fill,surfaceY}|null`: loaded/open flat physical fill sample, half-open vertical boundary. Renderers may sample cell fill and neighbors via getCell plus loaded callbacks; derive display-only slope/current later. Movement/machines use the sample, extraction, insertion interfaces only; no duplicated movement or Resonance machinery.
- `wake(x,y,z)`: enqueue existing liquid in this cell and its six face neighbors after a host block edit, load/unload transition or other relevant change. Unloaded boundaries are impermeable and retained; host must wake the affected loaded boundary cells on reload. No offline catch-up, world scan or automatic cross-chunk generation. Chunk eviction storage/restore adapter is later work.
- `tick(limit=maxVisits) => {visited,moved,changed,pending}`: FIFO bounded by configured maxVisits and initial queue count; gravity first, then fixed +X,+Z,-X,-Z equalization with integer half-difference and total lateral limit. No sideways transfer while a compatible passable cell below can receive gravity flow. Conservative ordered in-place update; deterministic for same input/callback/queue order. A cell may be revisited across ticks; budget is visits, not elapsed time or global fluid time. Changed coordinates are unique for this call, including emptied cells. Caller tracks external insert/extract edits separately. MaxCells is a fail-closed resident-state cap, not production memory qualification. No tick reentrancy; callbacks must not mutate the engine. Failed host callbacks propagate; no transactional recovery for callback exceptions yet.
- `save() => {version:1,cells:[...],pending:[[x,y,z],...]}`: sparse standalone JSON-compatible snapshot including exact FIFO order. Restore with same descriptor/host configuration and `snapshot` argument; unknown version, malformed records, duplicate coordinates or invalid pending references fail closed. Does not alter historical game save schema; adapter, migration, atomic write, capacity admission, unload/rehydration and offline manifest are not integrated. Snapshot cost O(resident cells); no save per tick implied.
- `reactionRules:[{a,b,propose:(aCell,bCell)=>null|{consumeA,consumeB,product}}]`. `proposeReaction(ax,ay,az,bx,by,bz)` finds registered pair in either order, validates adjacent loaded/open unlike cells, calls pure owner rule in declared a/b order and validates exact integer consumption and product tag; returns frozen proposal with original cells or null. Read-only: no consumption, terrain mutation, heat, mixing or automatic dispatch on tick yet. Future transactional host executor must validate unchanged input, account quantities and products, and respect build protection. Lava A owns water-lava semantics; Acid A owns acid/water semantics; other pair rules need explicit ownership/creator approval. No other lane edits the dispatcher.
