# N3 opt-in single-network storage allocator
Contract: `resonance-network36-storage-allocation-v1`. No registration or save mutation. One Resonance energy type; all values safe nonnegative integer units per tick. Generation is a caller-verified availability budget, NOT proof of fuel withdrawal, ownership or delivery. The :24 draft #290 contract requires separate authorization/integer conversion before using this allocator. Devices are sorted by numeric priority ascending, then UTF-16 ID; basic safety devices should receive lower priority numbers than optional production. Storage sorted by ID, with independent capacity, inputRate, outputRate and charge. Output-rate remaining is tracked across all admitted devices in one tick. Failed device admission does not consume energy; survivors resume on the next invocation. Input objects are not mutated. A caller must explicitly carry returned charge into the next tick; no persistence or free-energy credit is created by this module. No channels, wireless links, chunk adapter, UI, damage, renderer, world edits, or block IDs are changed. This isolated N3 prototype is not an integrated network solver. Local targeted native tests: 7/7 passed on Node.js, before commit; committed-head CI and browser acceptance not yet claimed. Run `node --test tests/resonance-network36-storage-allocation.mjs`. Future integrator must verify generator authority and network connectivity, preserve original saves, and validate exact-head WebGL2 and offline PWA.
