## Proposed F1 renderer architecture (requires new explicit creator authorization)

1. **Opt-in only, isolated engine-owned branch.** Never change public old-world rendering or the legacy 25/34 surface/edited-shaft / 27 deep / 18 lowest near-chunk budgets. Preserve existing source ownership, original block IDs, collision, mining, Creative flight, save isolation, seed determinism and historical East Gallery open sky. No new repository, new public world profile, optional plugin or background job.
2. **Near chunks always have absolute scheduling priority.** Keep the current `chunks`, `pending`, `wanted`, `MeshFrameCadence` and GPU retry semantics as near-field authority. Introduce a *separate* bounded far-opaque cache and queue, not 75 normal active deep chunks (5×5×3). Never evict a healthy near-buffer to upload a far wall. Only consider far work after near `pending.size===0`, foreground running and the near section set settled.
3. **Source-driven selection, no arbitrary enclosure.** Reuse view yaw/pitch, exact source camera, depth section/near bounds, horizontally correct phone FOV, and bounded first-solid `world.get` rays. Only select source-solid world rock in outer ring two and the player's actual active section. Use `meshDepthSection` with the same production world/get semantics and 36-byte packed vertex stride. Never use fake colored quads, blanket sky suppression or a source-rock placeholder; preserve legitimate open caves.
4. **Hard memory and work caps.** Initial opt-in experiment: **at most 4 extra far opaque chunk buffers**, **1,048,576 additional live GPU geometry bytes**, **at most one far upload per eligible rendered frame**, and **≤3,264 source cell samples per planning event**. Recompute on meaningful chunk/yaw/pitch/world-epoch change, **never via a repeating background timer or on every mobile frame**. Reuse bounded candidate cache. Track actual allocated bytes, extra vertices, mesh upload time, draw calls, deferred retries and any excluded/uncovered far ray; freeze/defer far work on context loss or foreground suspend.
5. **Draw as genuine world geometry.** After the current sky and before transparent-water processing, issue opaque far buffers through the existing terrain shader, fog, depth testing and attribute format; near geometry remains authoritative at overlaps. Keep fully transparent water and all manual-pack overlays unchanged. Far candidates must not overwrite real walls or obstruct the actual source-controlled walkable AIR: all vertices come from real `world.get`/mesher.
6. **Invalidation and recovery.** Clear/revalidate on cave seed/profile switch, player depth-section transition, native WebGL context-loss/restoration, device resume and offline reload. Any genuine player edit affecting a far candidate invalidates its corresponding source-mesh cache without mutating saves. When far budget is insufficient, expose a verifiable **C6_UNRESOLVED_FAR_VISIBILITY** diagnostic and retain the release blocker; never silently raise the cap or substitute sky fog to obtain a false pass.
